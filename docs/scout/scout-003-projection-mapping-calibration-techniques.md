# Scout 003 - Projection Mapping Calibration Techniques

**Source / Question:** Which projection-mapping, structured-light, and camera-projector calibration techniques can RPG Map Projector borrow for fast physical-table calibration?
**Scouted:** 2026-05-30
**Scope:** Camera-projector homography, active projected patterns, fiducials, lens undistortion, structured light, mesh warping, and drift tracking for a local-first gateway rig.
**Status:** Filed

## Executive Recommendation

Adapt projection-mapping calibration mechanics, not projection-mapping/VJ tools wholesale.

The immediate product split should be:

1. Detect or mark the physical mat grid in camera space.
2. Calibrate projector pixels to camera/table coordinates with active projected evidence.
3. Warp the prepared map into projector pixels, with strict residual gates and manual fallback.

Passive mat-grid detection is still useful, but projection mapping gives the stronger path for projector-camera calibration because the app controls the projected pattern. The best near-term hardware spike is now a one-frame pattern with perimeter coded fiducials and interior circle targets, with target-adapted two-frame refinement and ChArUco kept as fallback challengers. Known camera and projector correction should be added before interpreting residuals as projection failure. Dense Gray-code or phase-shift structured light remains a setup/lab tool, not the default live workflow.

## Evidence

- OpenCV's homography APIs (`findHomography`, `warpPerspective`, and related calibration functions) are the direct math primitive for planar camera/projector mapping. See OpenCV's homography tutorial: <https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html>.
- OpenCV's camera calibration docs explicitly model lens distortion and explain why straight real-world lines can appear curved in camera images. This matters for the current real-home photos and argues for a camera-undistortion preprocessing path before judging homography residuals. See <https://docs.opencv.org/4.x/dc/dbb/tutorial_py_calibration.html>.
- OpenCV also exposes a fisheye calibration model. This matters if the capture source is an iPhone lens, wide-angle phone mode, or cheap wide-angle webcam: the first hardware packet should test whether normal pinhole/radial calibration is adequate before treating curved residuals as target or solver failure. See <https://docs.opencv.org/4.x/db/d58/group__calib3d__fisheye.html>.
- OpenCV supports known calibration targets such as chessboards, circle grids, and ChArUco/ArUco markers. These remove grid-ownership ambiguity by giving known point IDs/corners. See ArUco/ChArUco calibration docs: <https://docs.opencv.org/3.4/da/d13/tutorial_aruco_calibration.html>.
- OpenCV's ChArUco detection docs describe the marker-ID plus chessboard-corner hybrid that can deliver explicit IDs and subpixel interior corners from one projected board. See <https://docs.opencv.org/4.x/df/d4a/tutorial_charuco_detection.html>.
- OpenCV's current calibration-pattern docs cover checkerboards, symmetric/asymmetric circle grids, and ChArUco boards. The asymmetric-circle option matters because it gives anonymous circles enough structure for reliable ordering. See <https://docs.opencv.org/4.x/da/d0d/tutorial_camera_calibration_pattern.html>.
- OpenCV's ArUco detection docs show the marker-ID detection path that projected coded fiducials would reuse in the gateway. See <https://docs.opencv.org/4.x/d5/dae/tutorial_aruco_detection.html>.
- OpenCV's calib3d stack supports robust overdetermined homography and pose estimation primitives. Active calibration should prefer 12-30 correspondences with `findHomography` and robust rejection over the current exact four-point DLT used by the UI math. See <https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html> and <https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html>.
- OpenCV's USAC tutorial documents robust estimators beyond plain RANSAC. This is relevant for active residual checks where projected features may be missed, occluded, or falsely detected. See <https://docs.opencv.org/4.x/de/d3e/tutorial_usac.html>.
- OpenCV's ECC image-alignment API can refine an affine or homography warp by directly maximizing image correlation. This is relevant after a fiducial/circle seed: use point features for correspondence, then optionally refine against the whole captured active-pattern image and reject if holdout residual worsens. See <https://docs.opencv.org/4.x/dc/d6b/group__video__track.html>.
- A-contrario homography methods such as ORSA, and newer VSAC-style robust estimators, are useful as validation-gate references because they explicitly ask whether a model is meaningful enough rather than only returning the best model from noisy data. See <https://www.ipol.im/pub/art/2012/mmm-oh/> and <https://openaccess.thecvf.com/content/ICCV2021/html/Ivashechkin_VSAC_Efficient_and_Accurate_Estimator_for_H_and_F_ICCV_2021_paper.html>.
- AprilTag is a maintained fiducial-marker system used in robotics and can provide explicit marker identity and pose/corner data. Upstream repository: <https://github.com/AprilRobotics/apriltag>.
- AprilTag exposes detector tuning knobs such as image decimation, and OpenCV ArUco exposes detector parameters. These matter for a Raspberry Pi-class gateway: global detection can run on a decimated frame, then accepted marker/circle/corner ROIs can be refined at full resolution. See <https://github.com/AprilRobotics/apriltag#tuning-the-detector-parameters> and <https://docs.opencv.org/4.x/d1/dcd/structcv_1_1aruco_1_1DetectorParameters.html>.
- OpenCV structured-light Gray-code workflows can recover dense camera-to-projector correspondences, but require many pattern frames plus black/white shadow frames. This is powerful for hardware characterization or a setup wizard, not the fastest default live-play loop. See OpenCV's Gray-code capture/decode tutorials: <https://docs.opencv.org/master/db/d56/tutorial_capture_graycode_pattern.html> and <https://docs.opencv.org/master/dc/da9/tutorial_decode_graycode_pattern.html>.
- One-shot coded structured-light patterns such as De Bruijn sequences can recover correspondences faster than full Gray code, but add custom decoding and are harder to make robust than large projected marker IDs. See <https://arxiv.org/abs/1803.09058>.
- Bundle-adjusted single-shot projector-camera calibration is relevant if a physical calibration target is imperfect, warped, or only observed from one pose. It is a setup-profile fallback, not a live-table default. See Huang et al.'s single-shot projector-camera calibration work and repo: <https://arxiv.org/abs/1803.09058>, <https://github.com/BingyaoHuang/single-shot-pro-cam-calib/>.
- Target-adapted active calibration literature supports the two-step pattern already suggested by the synthetic harness: estimate rough geometry first, then project features where the target/camera can observe them cleanly. See Chien et al., Sensors 2013: <https://www.mdpi.com/1424-8220/13/2/2664>.
- Single-pose planar-target projector-camera calibration using Gray-code correspondence can simplify fixed-rig profiling, but it is still a multi-frame setup routine rather than a live-table path. See Lawal and Greenspan 2021: <https://arxiv.org/abs/2102.11395> and <https://www.scitepress.org/Papers/2021/103277/103277.pdf>.
- Projector-camera frame synchronization can matter if hardware tests show dropped frames, rolling bands, LCD response lag, or captured pattern mismatch. Pattern frames should carry visible IDs or fiducial markers so the camera can confirm which projected frame it captured. See Klein et al., Graphics and Visual Computing 2021: <https://www.sciencedirect.com/science/article/pii/S2666629421000164>.
- Projector-camera systems also have photometric/radiometric concerns: black/white or gray preflight frames can lock exposure, identify shadows, and make projected marker detection more reliable on colored or glossy mats. See the geometric/radiometric calibration treatment in <https://openaccess.thecvf.com/content_cvpr_2017/papers/Shahpaski_Simultaneous_Geometric_and_CVPR_2017_paper.pdf>.
- Capture and display pipelines can secretly transform the calibration image before CV sees it. Apple Continuity Camera features such as Center Stage, Desk View, Portrait Mode, and Studio Light are useful for calls but dangerous for calibration if they crop, reframe, relight, blur, or otherwise alter the frame. Record and disable these effects when using an iPhone as the fixed camera. See <https://support.apple.com/en-us/102546>.
- Projector and compositor features can similarly invalidate calibration. Auto-keystone, four-corner correction, digital zoom, display scaling, image processing modes, browser fullscreen dimensions, and projector-side warp should be disabled or recorded as rig-profile inputs. Keystone correction is explicitly a digital geometry correction, so hidden settings can look like algorithm error. See <https://support.philipsprojection.com/hc/en-us/articles/360012894660-FAQ-Keystone-Correction-Calibration>.
- Detection success is not the same as player-visible success. Projector-camera radiometric compensation literature is a reminder that brightness, room light, mat color/gloss, and projected map texture can matter after geometry passes. For MVP, record a projected-content legibility check before treating a geometric pass as table-ready. See <https://www.computationalimaging.org/publications/radiometric-compensation-through-inverse-light-transport/>.
- Camera calibration uncertainty and cross-validation become relevant if OpenCV reprojection RMS appears good while physical projection error remains high. `mrcal` is not a projector-camera solution, but its uncertainty framing is useful for judging whether a fixed camera profile is trustworthy. See <https://mrcal.secretsauce.net/index.html> and <https://mrcal.secretsauce.net/docs-3.0/uncertainty.html>.
- Plumb-line and calibration-harp distortion checks are useful when physical residuals curve even after a nominal camera profile passes. They validate straightness from long observed straight lines rather than relying only on checkerboard-style reprojection RMS. See Devernay/Faugeras-style straight-line distortion work <https://cir.nii.ac.jp/crid/1363107370789317120?lang=en> and IPOL calibration harp material <https://dev.ipol.im/~jirafa/lens-distortion-measurement/>.
- OpenCV remap/warp primitives can support a later piecewise mesh correction if a single homography is not good enough under projector lens distortion, camera lens distortion, or mat curl. See <https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html>.
- AprilGrid targets combine AprilTag-like identity with a grid layout and are relevant for reusable mat-edge strips, calibration cards, or assisted table setup where partial visibility and pose disambiguation matter. See Kalibr target docs: <https://github.com/ethz-asl/kalibr/wiki/calibration-targets>.
- OpenCV's sector-based checkerboard detector (`findChessboardCornersSB` and metadata variants) is not a detector for arbitrary wet-erase battle-mat lines, but it is a strong fallback for a dedicated printed or projected calibration board. See <https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html>.
- Topological grid finding from corner candidates, including Delaunay/quad-mesh filtering, is relevant if passive printed-grid detection resumes. It explicitly targets partial occlusion and radial distortion in calibration-grid detection. See Shu, Brunton, and Fiala 2010: <https://nrc-publications.canada.ca/eng/view/object/?id=842dd602-fa9e-4517-9055-3c5c36fd89bb>.
- Mixed point-and-line homography is relevant if projected circles blur or passive line evidence is stronger than point centers. Marker IDs can seed point correspondences while long projected or detected lines enter the solve directly as line constraints, avoiding fragile line-intersection extraction. See Dubrofsky/Woodham's point-plus-line homography reference: <https://citeseerx.ist.psu.edu/document?doi=3e3949e2b92fdff9dd8d21c6bfda3e387a68d5cf&repid=rep1&type=pdf>.
- EDLines and ELSED are fast line-segment extraction families worth remembering for low-compute passive or active-line evidence. They are not product solutions by themselves; they would feed integer-lattice or point-plus-line consensus. See <https://research.itu.edu.tr/en/publications/edlines-a-real-time-line-segment-detector-with-a-false-detection-/> and <https://arxiv.org/abs/2108.03144>.
- Low-spatial-frequency and circular fiducials such as LFTag and CCTag are materially different from ArUco/AprilTag squares and may survive projector defocus, low resolution, or glare better. Implementation complexity makes them fallback candidates, not first defaults. See <https://arxiv.org/abs/2006.00842> and <https://www.cv-foundation.org/openaccess/content_cvpr_2016/papers/Calvet_Detection_and_Accurate_CVPR_2016_paper.pdf>.
- Stanford's old calibration-grid detector is not a dependency candidate, but its algorithmic pattern is useful: detect grid features, match against known geometry, and reject by RMS homography error. See <https://graphics.stanford.edu/software/findgrid/>.
- Moreno/Taubin's projector-camera calibration work is a useful reference for treating the projector as an inverse camera and for a later fixed-rig profile, but it is setup/lab complexity rather than the first live-table flow. See <https://mesh.brown.edu/calibration/>.
- Open-source projection-mapping tools such as ofxPiMapper and MapMap are useful UX references for manual handles, surfaces, and mesh editing, but they do not solve this product's mat-grid ownership or DM workflow. See <https://github.com/kr15h/ofxPiMapper> and <https://github.com/mapmapteam/mapmap>.

## Candidate Techniques

| Technique | Fit | Timing | Recommendation |
|---|---|---:|---|
| Sparse projected-point homography | Project 4-20 known dots/corners, capture them, solve projector-to-camera/table homography. | Fast | Spike first once projector/camera hardware exists. |
| Projected coded fiducials | Project large known-ID markers or marker-like codes at known projector pixels, detect IDs/corners in camera space, solve overdetermined projector-camera homography. | Fast | Spike alongside sparse dots; this is the safer correspondence path when anonymous dots are ambiguous. `npm run benchmark:active-fiducial-sim` keeps this as the robust first-frame seed. |
| One-frame perimeter fiducials plus interior circles | Project known-ID markers around the pattern perimeter and precise circle targets across the interior in one frame; use marker IDs to seed circle assignment, then solve from all detected features. | Fast | Current synthetic leader. Expanded 240-trial run accepted 240/240 with 0.086 px median p95 surface error after masking marker regions before circle detection, beating the previous two-frame target-adapted branch while requiring one frame. |
| Two-frame fiducial plus circle refinement | Project coded fiducials first for robust IDs, then project a circle grid/residual frame and assign circle centers from the fiducial-seeded homography. | Fast to moderate | Keep as a hardware fallback and residual-check option. The target-adapted surface-circle variant stayed robust in the expanded run, but was beaten by the one-frame perimeter composite. |
| Target-adapted closed-loop sparse pattern | Estimate rough geometry, then project the second pattern where the camera/target can see high-value features cleanly. | Fast to moderate | Keep as the first escalation if the one-frame composite fails under blur, glare, or occlusion; it is more table-friendly than dense structured light. |
| Projected ChArUco board | Project one board that combines marker IDs with chessboard-style interior corners. | Fast | Keep as a mature OpenCV fallback challenger. Expanded synthetic evidence nearly accepted 240/240, but full-surface holdout is weaker than the perimeter-fiducial/interior-circle branch. |
| Projected or printed AprilGrid | Use a grid of AprilTag-like markers for explicit identity plus partial-visibility tolerance. | Fast to moderate | Consider for reusable mat-edge strips, a setup card, or a projected fallback if ArUco/ChArUco ambiguity appears on real hardware. |
| Closed-loop sparse active calibration | Project a first sparse pattern, solve, then project a second residual-check pattern at predicted mat locations and update if the residual is too high. | Fast to moderate | Adapt before dense structured light; it preserves table speed while catching bad first-frame solves. |
| Robust overdetermined homography/PnP | Use many correspondences with robust rejection instead of exact four-corner DLT. | Fast | Adopt for active calibration and marker-assisted calibration. Prefer USAC/RANSAC-style gates before accepting a solve. |
| ECC/direct image-alignment refinement | Use feature correspondences for an initial homography, then refine the warp against the full active-pattern image by correlation. | Local moderate | Adapt as a post-seed challenger; reject if it worsens feature holdout residuals or converges to a prettier but wrong alignment. |
| A-contrario/VSAC adequacy gates | Add model-meaningfulness and adaptive-threshold refusal logic around homography candidates. | Local moderate | Adapt as a validation reference before custom solver work; useful for wrong-confident prevention. |
| Mixed point-and-line homography | Combine marker/circle point correspondences with long projected/detected line constraints. | Local moderate | Hardware challenger if circle centers blur or line targets survive projector optics better than dots. |
| Printed fiducial frame or corner tabs | Place ArUco/ChArUco/AprilTag markers at known mat-relative points. | Fast | Spike as an assisted fallback; keep markers outside play area when possible. |
| Projector-as-inverse-camera rig profile | Calibrate fixed projector intrinsics/distortion once for a mounted rig, then combine with per-placement table calibration. | Setup-only | Defer until hardware is fixed, but do not ignore it: synthetic projector-distortion stress shows raw commanded-pixel homography can have large edge error. |
| Camera intrinsics and undistortion | Calibrate the fixed camera once, undistort every calibration frame. | Setup-only | Add before interpreting curved-line failures as detector failures. |
| Camera model selection | Test whether the capture path should use normal pinhole/radial calibration, OpenCV fisheye calibration, or another model. | Setup-only | Add to the first hardware packet, especially for iPhone or wide-angle webcam capture. |
| Camera capture preflight | Lock lens/source, orientation, stabilization/effects, exposure, and remote-camera processing. | Fast support | Add before judging calibration quality when using iPhone/Continuity Camera or any smart camera path. |
| Camera-profile uncertainty checks | Cross-validate the camera profile and treat uncertainty as a gate on downstream calibration confidence. | Setup-only | Add only if physical residuals contradict apparently good camera RMS/reprojection numbers. |
| Plumb-line / calibration-harp distortion self-check | Validate camera/projector straightness from long observed straight-line patterns when residuals look curved. | Setup-only | Defer until physical residuals show curvature or a cached profile looks stale. |
| Projected circle/dot grid | Project a known dot lattice, detect blob centers, fit correspondences. | Fast to moderate | Strong active alternative to AI dots because the app owns the dot coordinates. Synthetic evidence shows lower residual than fiducials when all points are detected, but more refusal risk under occlusion because the points are anonymous. The asymmetric circle-grid branch is more precise than the symmetric branch when detected, but still had one synthetic refusal. |
| Projected/printed checkerboard SB target | Use OpenCV's sector-based checkerboard detector on a controlled printed or projected target. | Fast to moderate | Useful for dedicated setup boards; not a passive detector for arbitrary battle-mat gridlines. |
| Photometric preflight frames | Project black/white/gray frames to set exposure and shadow masks before marker/dot detection. | Fast support | Keep as optional accuracy hardening. Synthetic stress showed no acceptance gain because raw markers already accepted, but normalized frames improved residuals. |
| Projector/compositor preflight | Disable or record auto-keystone, four-corner correction, digital zoom, display scaling, browser fullscreen size, and projector-side processing. | Fast support | Add before hardware solver tuning; hidden projector correction can invalidate cached profiles and masquerade as bad homography. |
| Pattern-scale sweep | Vary marker size, circle radius, line width, and brightness at real throw distance. | Fast support | Add before rejecting ArUco, ChArUco, circles, or line targets; a target family may fail only because features are too small, dim, blurred, or glossy. |
| Frame-ID synchronization markers | Encode each projected calibration frame with an ID so captured frames can be matched to the intended pattern. | Fast support | Add if real hardware shows pattern/capture mismatch, rolling-band artifacts, dropped frames, or display latency issues. |
| One-shot coded structured light | Project one coded pattern, decode correspondences. | Fast if it works | Spike only if projected coded fiducials fail and dense Gray code is too slow. |
| Gray-code structured light | Project many binary patterns to recover dense projector-camera mapping. | Slower | Defer to hardware characterization or setup wizard if sparse homography/mesh fails. |
| Sinusoidal/phase-shift structured light | Project phase-shift patterns for high-accuracy dense correspondences. | Slower | Defer to lab characterization; too pattern-heavy for the first live-table loop. |
| Integer-lattice RANSAC from passive lines/intersections | Infer grid coordinates from Hough/LSD line segments or junctions. | Local fast | Continue as optional passive helper, but current line-only probes do not beat AI dot consensus. |
| EDLines/ELSED line evidence | Replace broad Hough/LSD tuning with faster line segment extraction for passive or projected-line evidence. | Local fast | Defer; spike only if passive line evidence remains needed after active/fiducial routes. |
| Topological passive grid fitting | Detect corner candidates, build Delaunay/quad mesh topology, then fit/reject a regular grid under distortion and occlusion. | Local moderate | Add to the passive-grid backlog if AI/dot-assisted parsing stalls; it is more relevant than generic texture-lattice methods. |
| Known-geometry passive grid verification | Detect candidate features, match to known grid geometry, and reject by homography/RMS error. | Local fast | Use as a guardrail pattern for passive candidates and assisted fiducial strips; do not adopt old unmaintained binaries. |
| Piecewise mesh warp after homography | Store local residuals and prewarp projected map with `remap`. | Fast after setup | Keep as diagnostic/fallback. Synthetic residual mesh improved projector-distortion error but did not reach the known-compensation result. |
| Decimated ROI plus subpixel refinement | Detect globally on a decimated frame, then refine accepted marker/corner/circle ROIs at full resolution. | Fast | Adopt as the Raspberry Pi benchmark shape once hardware exists. |
| Projected-content visibility check | After geometry passes, project representative grid and map colors/textures under room light and record legibility. | Fast support | Add to physical validation so the product does not mistake geometric calibration for a usable table projection. |
| Low-frequency or circular fiducials | Test LFTag/CCTag-style markers if square fiducials fail under blur, glare, or defocus. | Fast to moderate | Defer behind ArUco/AprilTag/ChArUco; useful fallback family, not first implementation. |
| Temporal lock-on/drift detection | Track known points/fiducials frame-to-frame to detect bumps or stale calibration. | Live cheap | Add after a real calibration loop exists. |

## Adoption Decision

- Decision: Adapt
- Why: Projection mapping provides the right calibration architecture, but generic projection-mapping apps target arbitrary surfaces and manual visual mapping. This product needs battle-mat grid ownership, fast DM controls, and a local gateway loop.
- Follow-up owner: Story 001 physical calibration pass. ADR-001 now adopts the layered calibration architecture; create a follow-up ADR before adopting a durable fiducial implementation, non-browser CV runtime, dense structured-light setup flow, or mesh-warp model.

## Recommended Spike Shape

When hardware is available, test these in order:

1. Compare the new one-frame perimeter-fiducial/interior-circle pattern against one-frame projected coded fiducials, projected ChArUco, static two-frame fiducial-plus-circle refinement, and target-adapted second-frame circles: project known marker IDs, solve an overdetermined homography, then optionally project or assign circle/residual points from the marker-seeded homography.
2. Compare symmetric and asymmetric sparse dots/circles only as simpler active alternatives; keep refusal honest when circle ordering or missing points break correspondence.
3. Add camera intrinsics/undistortion for the fixed camera before interpreting curved residuals as projection failure.
4. Decide whether the camera source needs normal pinhole/radial calibration, fisheye calibration, or another model; lock phone-camera effects, orientation, lens/source, exposure, and stabilization before judging residuals.
5. Disable or record projector auto-keystone, four-corner correction, digital zoom, display scaling, browser fullscreen size, and projector-side processing before caching or comparing profiles.
6. Sweep marker size, circle radius, line width, and brightness at real throw distance before rejecting a target family.
7. Benchmark decimated global detection plus full-resolution ROI/subpixel refinement as the Raspberry Pi feasibility shape.
8. Add one residual-check frame at predicted mat locations if the first solve is above threshold.
9. Add frame IDs or visible sync markers if captured frames can be mismatched to projected patterns on the real projector/camera pair.
10. Try a printed fiducial strip, AprilGrid strip, setup card, or corner tabs outside the play area; solve mat-to-camera coordinates from explicit marker IDs.
11. Combine active projector-camera mapping with passive or fiducial mat-grid coordinates to project a 5 ft and 10 ft source grid.
12. Project representative map colors/textures after the geometric check to verify table legibility under room lighting.
13. If residuals remain curved or edge-heavy after known camera/projector correction, spike a small mesh correction, ECC refinement from the feature-seeded homography, plumb-line/harp straightness checks, one-shot coded pattern, Gray-code setup routine, or phase-shift setup routine.
14. If projected circles fail because of blur/glare but lines remain strong, test marker-seeded projected lines with a point-plus-line homography before escalating to dense structured light.
15. If camera calibration numbers look good but physical alignment remains poor, add camera-profile uncertainty/cross-validation before blaming the active pattern.

## Synthetic Harness Evidence

`npm run benchmark:active-fiducial-sim` renders active calibration patterns, warps them through the same randomized camera/projector geometry with mild blur/noise/occlusion, and solves an overdetermined projector-to-camera homography with RANSAC:

- projected coded fiducials: ArUco marker IDs/corners provide explicit correspondences,
- projected ChArUco: marker IDs plus board geometry provide explicit interior-corner correspondences,
- one-frame composite fiducial/circle patterns: marker IDs seed circle assignment in the same frame, avoiding a second projected pattern when the targets are visually separable,
- projected circle grid: anonymous symmetric or asymmetric circle centers are assigned by row/column order,
- static two-frame fiducial plus circle refinement: marker IDs seed the homography, then detected circle centers in a second frame are assigned by nearest projected point and included in a refined solve,
- target-adapted two-frame refinement: the marker seed chooses broader second-frame surface-circle positions before detection and assignment.

Current expanded synthetic run (`npm run benchmark:active-fiducial-sim -- --trials 240 --seed 20260531`):

- projected coded fiducials: 240/240 accepted, mean detected markers 19.688/20, median p95 feature error 0.193 px, median p95 surface error 0.434 px,
- projected circle grid: 220/240 accepted, mean detected circles 18.333/20, median p95 feature error 0.053 px, median p95 surface error 0.150 px,
- projected ChArUco board: 239/240 accepted, mean detected corners 29.379/30, median p95 feature error 0.186 px, median p95 surface error 0.385 px,
- projected asymmetric circle grid: 228/240 accepted, mean detected circles 33.25/35, median p95 feature error 0.041 px, median p95 surface error 0.178 px,
- one-frame center fiducials plus surface circles: 240/240 accepted, mean detected/assigned features 104.575, median p95 feature error 0.147 px, median p95 surface error 0.192 px,
- one-frame perimeter fiducials plus interior circles: 240/240 accepted, mean detected/assigned features 82.767, median p95 feature error 0.071 px, median p95 surface error 0.086 px,
- static two-frame fiducial plus circle refinement: 240/240 accepted, mean detected/assigned features 98.487, median p95 feature error 0.156 px, median p95 surface error 0.372 px,
- target-adapted fiducials plus surface-circle refinement: 240/240 accepted, mean detected/assigned features 113.392, median p95 feature error 0.133 px, median p95 surface error 0.174 px,
- point-level lens stress: raw distorted-camera homography compared to undistorted truth accepted 86/240 with 3.341 px median p95 error, while known camera undistortion accepted 240/240 with 0.102 px median p95 error,
- point-level projector-distortion stress: raw commanded-pixel homography accepted 0/240 with 21.512 px median p95 surface error, residual-mesh correction accepted 0/240 with 7.778 px median p95 surface error, and known projector compensation accepted 240/240 with 0.090 px median p95 surface error,
- photometric preflight stress: raw frames and black/white normalized frames both accepted 240/240, but normalization improved marker feature p95 from 0.181 px to 0.115 px and surface p95 from 0.420 px to 0.315 px,
- speed-aware split: one-frame perimeter fiducials plus interior circles are now both the best synthetic branch and the fastest accepted one-frame branch,
- artifacts: `test-results/projected-fiducial-calibration-sim/`.

This does not prove table performance. It shows the current synthetic tradeoff: circle centers are most precise when fully detected, coded fiducials provide identity, and the new perimeter-fiducial/interior-circle pattern combines those advantages in one projected frame. The center composite pattern helped, but moving markers to the perimeter let interior circles cover the surface better and beat the previous two-frame target-adapted branch. The composite detector now masks detected marker regions before circle detection so white blobs inside ArUco markers cannot become circle candidates; the recommendation still held after that hardening. The lens and projector stresses are point-level geometry evidence, not detector evidence, but they show that raw distorted camera or projector pixels can look internally plausible while being wrong against corrected truth. Residual mesh correction helps in the projector-distortion stress but remains above the current acceptance threshold, so fixed-rig projector profiling is the stronger path if hardware shows edge-heavy residuals. Photometric preflight is not required by the synthetic accept gate yet, but the residual improvement makes it a cheap candidate if real glare, exposure, or contrast is unstable. The first physical projector/camera pass should compare the perimeter-fiducial/interior-circle pattern against ChArUco, plain fiducials, asymmetric circles, and target-adapted two-frame refinement, and should include camera intrinsics/undistortion plus projector-distortion awareness if residuals are curved or edge-heavy.

The sidecar projection-mapping scouts on 2026-05-30 did not change the main recommendation. They added follow-up references for target-adapted closed-loop sparse patterns, single-shot or single-pose setup-profile calibration, synchronization markers, AprilGrid targets, checkerboard-SB controlled targets, topological passive grid fitting, ECC post-seed refinement, a-contrario/VSAC refusal gates, mixed point-and-line homography, plumb-line distortion checks, EDLines/ELSED line evidence, Pi-oriented decimated ROI refinement, and low-frequency/circular fiducial fallbacks. Full scanner suites, RoomAlive-style stacks, PatchMatch/MRF near-regular texture detection, and learned U-Net grid-point detectors remain low-priority for this product.

## Risks And Open Questions

- Camera lens distortion can make a correct physical grid look wrong. Undistort first before judging homography failures.
- A wide-angle camera source may need a fisheye or other camera model; do not assume normal radial distortion is enough for iPhone or cheap wide-angle webcams.
- Smart camera pipelines can crop, stabilize, relight, blur, or reframe the image. Disable or record these effects before using a phone as the fixed calibration camera.
- Projector auto-keystone, display scaling, and hidden image processing can change the projected geometry after the app renders the pattern. Treat those settings as profile inputs or invalidators.
- Mat curl and non-planar surfaces break a single-plane model. MVP should prefer flattening the mat or accepting small local error before adding dense reconstruction.
- Projector-camera calibration is fragile if focus, zoom, resolution, exposure, or mount geometry changes. Cache profiles only with a fresh validation check.
- Geometric calibration can pass while the projected map remains too dim, low contrast, or illegible. Keep geometry and table-visibility validation separate.
- Fiducials are reliable but visible. Use removable tabs, edge strips, or calibration-only placement before live projection.
- Gray-code structured light is accurate but pattern-heavy. Use it as a setup or lab tool, not the default "players opened the door" flow.
- Projector/camera frame mismatch can masquerade as bad geometry. If real captures are inconsistent, add projected frame IDs before tuning the solver.
- Old calibration-grid binaries and broad scanner stacks may contain useful algorithms, but they should not become product dependencies without a fresh ADR.
